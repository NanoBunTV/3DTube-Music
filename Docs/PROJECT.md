# Project overview and decisions

## What it is

3DTube Music is a homebrew YouTube Music client for the Nintendo 3DS (C++, devkitPro / libctru / citro2d).
It plays audio only, has no ads (streams are fetched directly), and supports SponsorBlock, YouTube Music
search / albums / playlists / artists, a play queue with shuffle and repeat, and radio.

It started from the idea of porting [Pear Desktop](https://github.com/pear-devs/pear-desktop) (an Electron
YouTube Music wrapper) to the 3DS. That isn't possible: Electron/Chromium can't run on a 3DS. Instead the
project is based on [FourthTube](https://github.com/erievs/FourthTube) (GPLv3), a native 3DS YouTube client
that continued [ThirdTube](https://github.com/windows-server-2003/ThirdTube).

- **2026-10-13** : video removed entirely. Added the YouTube Music parser, play queue, now-playing screen,
  music search, album/playlist/artist pages, and the YouTube Music home feed. Switched the default player
  client to visionOS after the "song skips after one minute" bug (see YOUTUBE_API.md).
- **2026-10-13** : added lyrics; own icon, banner and banner sound (FourthTube's removed); all interface
  strings translated into the 6 other languages. Clean-up : removed FourthTube's channel scene, subscriptions
  (Home's Subscribed / New tabs), comment and caption code, like/dislike counts, and the YouTube channel /
  search / home parsers. Loading a track now takes one `player` request (plus SponsorBlock in parallel)
  instead of four sequential-ish requests.
- **2026-10-13** : sign-in confirmed working on hardware. Added the Library tab (Liked Music + playlists) using
  the regular YouTube API, since YouTube Music's API rejects the TV sign-in token; access tokens now refresh
  automatically. The owner decided against saved albums / artists via the TV API.
- **2026-10-13** : like button and "add to playlist" / "new playlist" on the now-playing screen. Prepared the
  first release, v1.0.0 (first planned as v0.1.0), for https://github.com/NanoBunTV/3DTube-Music : version scheme, updater re-enabled
  (pointing at that repo), CHANGELOG.md, install steps in the README. All GitHub Actions workflows removed
  (FourthTube's CI and CodeQL, and a release workflow) : the owner builds and releases from their PC.
  The generated banner chime was replaced by a sound file the owner supplied (they found the chime sounded bad).

## Decisions and why

| Decision | Reason |
|---|---|
| Base on FourthTube instead of writing from scratch | It already solves stream URLs, networking (libcurl + mbedtls), AAC decoding (FFmpeg) and the UI toolkit |
| Standalone repo, no shared history with FourthTube | The owner wants a separate, non-fork GitHub repo. Credits must stay in README / About |
| No video at all | Owner's call : "people can use the original FourthTube if they want video". Also frees ~4 MB of linear memory |
| Sign-in is optional, never required | Using a Google account with a client that impersonates official apps can get the account flagged |
| No ads, by design | Streams are fetched directly; ads are never requested. No Premium needed |
| SponsorBlock on by default, using the k-anonymity endpoint | Only a 4-character hash prefix of the video id is sent |
| In-app updater uses this project's releases only (`UPDATE_RELEASES_API_URL`) | It overwrites the running .3dsx / installs the .cia that the latest release serves, so it must never point at FourthTube's or anyone else's releases |
| Version scheme `vMAJOR.MINOR.PATCH`, tags match | The updater compares the numbers in the tag and `DEF_CURRENT_APP_VER`; the old "Alpha 0.1 (FourthTube Beta 34.1)" would have compared as 0.1.34.1 |
| Separate title ID / product code / data folder | Installs alongside FourthTube : unique ID `0xBEA12`, `CTR-3TM`, `/3ds/3DTubeMusic/` |
| Must stay GPLv3 | Derived from GPLv3 code. The FFmpeg submodule points at the modified FFmpeg source (LGPL requirement) |
| No local subscriptions / channel pages | They followed YouTube video channels. Channel links (`/channel/UC...`) open the YouTube Music artist page instead |
| Own artwork | Icon/banner are generated by `resource/art/` scripts : a white extruded double note on a violet-to-pink gradient. Deliberately not resembling YouTube Music's or TikTok's logos. The banner sound is the owner's own file, not generated |

## Owner preferences (for AI assistants)

- **Never run `git commit` or `git push`**, and don't stage changes. The owner handles all commits and pushes.
- The owner tests on a **New 3DS** (no Old 3DS available).
- **No GitHub Actions / CI.** Builds and releases are made on the owner's PC (`.\build.ps1 release`, then a
  release created by hand on GitHub). Don't add workflows back.
- **Testing is on hardware only.** The owner tests builds on their New 3DS and reports results; don't try to
  test in the Azahar emulator (it was tried twice and doesn't work for this app). Don't drive the owner's
  desktop (screenshots, input).
- Pressing HOME stops audio. That's normal 3DS behaviour for applications; don't treat it as a bug.
